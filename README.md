# INSYS (자체 호스팅 버전)

claude.ai 아티팩트로 만들었던 개인 업무 일지 앱을, 외부 SaaS 없이 GitHub + Coolify로
직접 배포할 수 있는 형태로 옮긴 버전입니다. 화면(`static/index.html`)과 서버(`main.py`)만으로
동작하고, 이전 "바이브 레지스트리" 프로젝트와 동일한 구조(FastAPI + SQLite + Docker)를 따릅니다.

## 무엇이 달라졌나 (아티팩트 버전 대비)

- **저장소**: `window.storage`(개인 Claude 계정) → 이 서버의 SQLite DB(`/data/app.db`). 회사가
  직접 통제하는 인프라 안에 데이터가 있습니다.
- **로그인/권한**: 없음 → 이메일 가입 + 즉시 사용 가능. 각자 자기 계정으로 로그인해서
  **자기 데이터만** 보고 씁니다 (계정관리자도 다른 사람의 기록 내용은 조회할 수 없습니다 — 계정
  역할/삭제 관리만 가능).
- **AI 호출**: 브라우저가 Anthropic에 직접 요청 → 이 서버가 대신 요청합니다. API 키가 브라우저에
  노출되지 않고, 서버의 고정 IP로 호출되므로 IP 허용 목록이 필요한 사내 API(예: 웍스AI)에도
  대응할 수 있습니다. 이미지/PDF를 올려 회사 비전을 자동 정리하는 기능도 서버가 대신 처리합니다.
- 그 외 화면과 기능(MBO 목표, 기록, 조회, 리더십 진단 10개 항목, 본인 진단, 이름 익명화, 앱 내부
  "관리자 설정"(회사 비전/평가요소) 등)은 아티팩트 버전과 동일합니다.

## 두 가지 "관리자" 개념이 있어요 — 헷갈리지 않게 정리

이 앱에는 이름이 비슷한 권한 개념이 두 가지 있습니다.

1. **계정관리자** (서버 로그인 계정의 역할, `main.py`가 관리) — 사이드바의 **"팀원 계정 관리"**
   탭에서 팀원 계정의 역할 변경/삭제를 할 수 있습니다. 첫 번째로 가입한 사람이 자동으로
   계정관리자가 됩니다.
2. **관리자(정)/관리자(부)** (앱 안의 개인 데이터 설정, 사용자별로 각자 관리) — 사이드바의
   **"관리자 설정"** 탭(회사 비전/조직문화, 리더십 평가요소)에 접근할 수 있는지를 결정합니다.
   각 사용자가 로그인해서 처음 데이터를 만들 때 스스로 "관리자(정)"으로 시작하고, "권한 관리"
   화면에서 다른 사람에게 넘기거나 관리자(부)를 지정할 수 있습니다. **이건 계정관리자 역할과
   무관합니다** — 계정관리자가 아니어도 관리자(정)일 수 있고, 그 반대도 가능합니다.

혼란스러우시면, 실제 운영 시에는 **"계정관리자 = 관리자(정)"으로 통일해서 운영하시는 걸
추천**드려요.

## 구조

```
main.py            FastAPI 서버 (인증/승인, 데이터 저장, AI 프록시, 정적 파일 서빙)
static/index.html  화면 전체 (로그인 화면 + 앱 화면, 빌드 과정 없는 순수 JS)
requirements.txt   fastapi, uvicorn
Dockerfile          컨테이너 이미지 정의
```

## 계정 / 권한

- 비밀번호는 서버에서 PBKDF2로 해싱해서 저장합니다 (평문 저장 안 함).
- **관리자 승인 없이 누구나 가입 즉시 바로 사용할 수 있습니다.** (승인 대기 절차를 없앴습니다 —
  "누군가 내 가입을 심사한다"는 느낌 자체를 줄이기 위한 선택입니다.)
- **첫 번째로 가입하는 사람이 자동으로 관리자가 됩니다.** 이후 가입자는 전부 일반 권한으로
  가입과 동시에 바로 로그인됩니다.
- **`ALLOWED_EMAIL_DOMAIN`은 기본값이 `xicna.com`으로 이미 설정되어 있습니다.** `@xicna.com`
  이메일만 가입할 수 있고, 다른 도메인이 필요하면 배포 시 이 환경변수로 덮어쓰면 됩니다.
  승인 절차가 없어진 만큼 이 도메인 제한이 사실상 유일한 가입 문턱입니다. 다만 이메일 소유
  여부를 실제로 검증하는 절차(인증 메일 발송 등)는 없으니, 이 도메인 이메일 형식만 맞으면
  가입 자체는 됩니다.
- 관리자는 사이드바의 **"팀원 관리"** 탭에서: 역할 변경(관리자 ↔ 일반), 팀원 내보내기(계정 삭제)
  를 할 수 있습니다. 주로 **퇴사자 계정 정리** 용도로 쓰시면 됩니다. 마지막 남은 관리자는
  강등/내보내기가 되지 않도록 막혀 있습니다.
- **각 팀원의 업무 기록(목표, 기록, 구성원 메모 등)은 본인 계정에만 귀속되며, 관리자를 포함해
  다른 사용자는 앱 화면상 볼 수 없습니다.** 다만 이건 애플리케이션 레벨의 제한이고, 서버의
  `/data/app.db` 파일 자체는 암호화되어 있지 않아 그 파일에 직접 접근 가능한 사람(서버/인프라
  관리자)은 내용을 열어볼 수 있습니다. 이 점까지 막으려면 클라이언트 측 암호화가 추가로
  필요합니다.
- 로그인은 서버가 발급한 세션 쿠키(httpOnly)로 유지됩니다.

## AI 연동 설정 (환경변수)

| 변수 | 설명 | 기본값 |
|---|---|---|
| `AI_PROVIDER` | `anthropic` \| `openai` \| `worksai` \| `custom` | `anthropic` |
| `AI_API_KEY` | 사용할 API 키 | (필수) |
| `AI_MODEL` | 모델 이름 (anthropic/openai 전용) | `claude-sonnet-4-6` |
| `AI_BASE_URL` | 커스텀 엔드포인트 | 제공자별 기본 URL |
| `AI_AGENT_ID` | **웍스AI 전용, 필수** — 사용할 에이전트 ID | (없음) |

### 웍스AI 연동 (`AI_PROVIDER=worksai`)

이 서버는 웍스AI **"에이전트 대화 API v2"**의 단발 JSON 경로(`POST /v2/chat/json`)를 그대로
구현해뒀습니다. 설정할 값:

| 변수 | 값 | 비고 |
|---|---|---|
| `AI_PROVIDER` | `worksai` | |
| `AI_API_KEY` | 웍스AI에서 발급받은 키 (`wrks_...`) | API 키 관리 화면에서 발급 |
| `AI_BASE_URL` | `https://gateway-api.wrks.ai` (기본값이라 생략 가능) | |
| `AI_AGENT_ID` | 사용할 에이전트의 `id` | 아래 방법으로 확인 |

**에이전트 ID 확인 방법**: 아래처럼 호출하면 사용 가능한 에이전트 목록이 나옵니다.
```bash
curl -X GET "https://gateway-api.wrks.ai/v2/agents" -H "API-KEY: {발급받은 키}"
# → {"result":"ok","data":[{"id":12,"name":"사내 규정 비서"}]}
```
여기서 나온 `id` 값을 `AI_AGENT_ID`에 넣으세요. 이 앱의 용도(업무 기록 분류, 코멘트 작성 등)에
맞는 범용 대화 에이전트를 하나 새로 만들어서 그 ID를 쓰시는 걸 권장합니다 (특정 업무 전용
에이전트를 쓰면 시스템 프롬프트가 충돌할 수 있어요).

**웍스AI 특유의 동작**:
- 호출할 때마다 로그인한 직원의 이메일을 `X-Actor-User-Email` 헤더로 자동으로 실어 보냅니다 —
  웍스AI 쪽 사용량/감사 로그가 실제 호출한 직원 기준으로 남습니다.
- 응답에서 `data.message` 필드를 텍스트로 사용합니다. 만약 웍스AI 쪽 응답 스키마가 향후
  바뀌어서 이 필드가 비어있으면, 에러 메시지에 원본 응답을 그대로 담아 보여주도록 만들어뒀으니
  그 메시지를 보고 `main.py`의 `ai_complete` 함수 중 `worksai` 분기를 수정하면 됩니다.
- IP 허용 목록에 이 서버(Coolify)의 아웃바운드 IP를 등록해야 호출이 성공합니다.

**참고**: 지금 이 서버는 프롬프트를 그대로 전달만 하고, 이름 익명화는 여전히 브라우저(JS)
쪽에서 처리합니다. 더 강하게 강제하려면(사용자가 브라우저에서 우회 못 하도록) 익명화 로직을
서버로 옮기는 작업이 추가로 필요합니다.

## 로컬 실행

```bash
pip install -r requirements.txt
DB_PATH=./data/app.db COOKIE_SECURE=false AI_API_KEY=sk-ant-... uvicorn main:app --reload
```

`http://localhost:8000` 접속. (`COOKIE_SECURE=false`는 로컬 http 환경에서 쿠키가 저장되게
하기 위함 — 운영 환경에서는 반드시 `true` 또는 미설정 상태로 두세요.)

## Coolify 배포

1. 이 저장소를 GitHub에 올리기
2. Coolify에서 새 애플리케이션 생성 → 이 저장소 연결, 빌드 팩은 **Dockerfile** 선택
3. **Persistent Storage(볼륨)** 추가: 컨테이너 경로 `/data`로 지정 → 재배포해도 데이터가
   안 지워집니다.
4. 환경변수 설정:
   - `AI_API_KEY` (필수)
   - `AI_PROVIDER`, `AI_MODEL`, `AI_BASE_URL` (필요시)
   - `ALLOWED_EMAIL_DOMAIN` (예: `company.com`)
   - `DB_PATH=/data/app.db`, `COOKIE_SECURE=true` (기본값으로 충분)
5. 포트 `8000` 노출, 배포
6. 배포된 서버의 아웃바운드 IP를 확인해서, 사내 AI API를 쓴다면 그쪽 허용 목록에 등록

## 데이터 백업

`/data/app.db` 파일 하나가 전부입니다. 이 파일만 주기적으로 백업하면 계정 + 전체 팀원의
업무 기록이 통째로 보존됩니다.

## 기존 아티팩트 데이터 옮기기

아티팩트 버전에서 쓰던 "관리 > 데이터 내보내기"로 JSON 파일을 받아두셨다면, 로그인 후
브라우저 개발자도구 콘솔에서 아래처럼 실행해 그대로 옮길 수 있습니다 (가져오기 API가 별도로
없으므로 임시 방법입니다):

```js
fetch('/api/data', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ data: /* 내보낸 JSON 파일 내용을 여기 붙여넣기 */ })
});
```
